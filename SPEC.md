# SPEC.md — Aghedo Agency Personal Freelance IT Support Website

## 1. Project Overview

Build a professional freelance IT support website for **Aghedo Agency**, the personal freelance agency of **Norman Aghedo**.

The website’s primary goal is to get prospective clients to **hire Norman as a freelance IT support provider**. It should position him as reliable, calm, practical, and trustworthy, with real help desk and desktop support experience across healthcare, corporate, accounting, and education environments.

The site should not present Norman primarily as a job seeker. It should present him as a freelancer who provides IT support services to individuals, small businesses, nonprofits, remote teams, schools, and small organizations.

The website should be deployed at:

```txt
https://aghedo.agency
```

Primary contact email:

```txt
norman@aghedo.agency
```

## 2. Core Positioning

### Primary Brand Statement

Aghedo Agency provides reliable freelance IT support for small teams, professionals, and organizations that need practical help with computers, software, user accounts, devices, connectivity, and day-to-day technical issues.

### Short Positioning Statement

Reliable freelance IT support built on clear communication, honest guidance, and dependable follow-through.

### One-Sentence Pitch

Aghedo Agency helps small teams and busy professionals solve everyday technology problems through calm, practical, and trustworthy IT support.

### What the Site Must Communicate Quickly

Within 5 seconds, visitors should understand:

1. Norman provides freelance IT support.
2. He helps with common business and personal tech problems.
3. He has real professional help desk and desktop support experience.
4. He communicates clearly and works honestly.
5. They can contact him directly at `norman@aghedo.agency`.

## 3. Target Audience

### Primary Audiences

- Small businesses without dedicated IT staff.
- Independent professionals who need technical help.
- Remote workers who need device, software, or account support.
- Nonprofits and community organizations.
- Schools, tutoring centers, or small education-related organizations.
- Small teams that need occasional or recurring IT support.

### Secondary Audiences

- Businesses seeking contract help desk support.
- Organizations needing short-term IT support coverage.
- People who want patient, plain-language technology help.

The site should feel:

- Calm
- Trustworthy
- Practical

## 5. Faith and Values Positioning

Norman is one of Jehovah’s Witnesses. This should be mentioned only as a **source of professional values**, not as a central sales message and not as religious promotion.

### Correct Framing

The site may explain that Norman’s background as one of Jehovah’s Witnesses has contributed to consistent training in:

- Effective communication
- Principled honesty
- Patience
- Respect for others
- Strong work ethic

This should support the business message: clients can expect clear communication, honest recommendations, and dependable follow-through.

### Incorrect Framing

Do not make the website feel like it is preaching, recruiting, or pushing faith. Do not put this in the main hero headline. Do not overuse religious language.

### Suggested About Section Language

Norman’s approach to IT support is shaped by practical experience and by values developed through consistent training as one of Jehovah’s Witnesses. That training has emphasized effective communication, principled honesty, patience, respect for others, and a strong work ethic. Those qualities shape how he supports clients, especially when technical problems are stressful, confusing, or time-sensitive.

## 9. Visual Design Direction

### Overall Aesthetic

The design should feel like a reliable, modern IT support provider. It should be clean, grounded, and easy to read.

The aesthetic should combine:

- Professional IT support
- Calm technical confidence
- Human service
- Trustworthiness

Avoid clutter, overly bright gradients, stock-photo cheesiness, fake corporate polish, and “hacker” visuals.

### Suggested Color Palette

Use a restrained palette.

#### Primary

Deep navy:

```txt
#0F172A
```

Use for headings, nav, footer, and high-contrast sections.

#### Secondary

Slate blue:

```txt
#334155
```

Use for body text, secondary headings, and supporting copy.

#### Accent

Reliable blue:

```txt
#2563EB
```

Use for buttons, links, active states, icons, and highlights.

#### Soft Background

Cool light gray:

```txt
#F8FAFC
```

Use for page backgrounds and alternate sections.

#### Card Border

Light slate:

```txt
#E2E8F0
```

Use for card borders, dividers, and subtle outlines.

#### Success / Trust Accent

Muted green:

```txt
#16A34A
```

Use sparingly for trust indicators, check icons, or “available for freelance support” badges.

### Typography

Use a clean sans-serif typeface.

Recommended Google Fonts:

- Inter
- IBM Plex Sans
- Source Sans 3

Preferred: **Inter**

### Type Scale

Use a modern but restrained scale.

- H1: 48–64px desktop, 36–42px mobile
- H2: 32–42px desktop, 28–34px mobile
- H3: 22–26px
- Body: 16–18px
- Small text: 14px

### Layout

Use a max-width container:

```txt
max-width: 1120px
```

Use generous spacing:

- Section vertical padding: 80–112px desktop
- Section vertical padding: 56–72px mobile
- Card padding: 24–32px
- Border radius: 16–24px

### Imagery

The site can work with or without a professional photo. If a photo is available, use it on the About page or in the hero. If no photo exists, use abstract but subtle IT support visuals.

Acceptable visual motifs:

- Soft grid backgrounds
- Terminal-style snippets without hacker clichés
- Clean iconography
- Desk/workstation imagery

Avoid:

- Glowing green code
- Generic call-center stock photos
- Overly religious imagery
- Clip art

Suggested icons:

- Direct
- Calm
- Capable
- Honest
- Easy to understand

- Buzzwords

- Religious persuasion

- Freelance IT support
- Help desk support
- Desktop support
- Remote support

- Dependable follow-through

- Enterprise-grade
- World-class
- Revolutionary
- Digital transformation

- Guaranteed same-day response unless true.

- Named client work without permission.

## 17. Accessibility Requirements

Meet WCAG-friendly basics.

Required:
- Semantic HTML landmarks
- Keyboard-accessible navigation
- Visible focus states
- Sufficient color contrast
- Alt text for meaningful images
- Empty alt text for decorative images
- Proper heading hierarchy
- Form labels connected to inputs
- Error messages associated with fields
- Buttons and links with clear accessible names
- Reduced motion support for animations

## 18. Performance Requirements

The website should be fast and lightweight.

Targets:
- Lighthouse Performance: 90+
- Accessibility: 95+
- Best Practices: 95+
- SEO: 90+

Implementation guidance:
- Use optimized images.
- Avoid large animation libraries unless already part of the stack.
- Use SVG icons where possible.
- Avoid autoplay video.
- Avoid heavy background effects.
- Use responsive images.
- Minimize JavaScript for static content.

## 19. Recommended Tech Stack

If building with Next.js:

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui for base components if useful
- Lucide React for icons
- React Hook Form + Zod for contact form validation
- Resend or similar for email delivery if backend is implemented

If building static:
